# 4. Testing

Run offline tests during development and real model integration before a pull request.

## Before a pull request

Complete [setup](1.setup.md) then run:

```bash
make pre-commit
make test-all
```

Or

```bash
make check
```

This runs `make pre-commit` (including strict docs), then `make test-all`: unit/NiceGUI component tests, then live LLM, Ollama
and API-to-model tests.

The full integration gate requires `INFERENCE_*` configured for a running Ollama service
with the selected model installed, including when you normally use a cloud provider.
Workers do not download models.
Missing services, failed cleanup, empty runs, skipped or deselected integration cases fail the gate.
Report unavailable integration as incomplete; collection or offline tests do not replace it.

## Focused checks

| Command                                                      | Scope / requirement                                   |
|--------------------------------------------------------------|-------------------------------------------------------|
| `make test-local`                                            | Offline unit and NiceGUI component/page simulations   |
| `make test-unit`                                             | Settings, logic and tooling tests                     |
| `make test-component`                                        | NiceGUI simulations without a browser or real backend |
| `make test-all`                                              | Every software suite, including live integration      |
| `make test-integration-check`                                | Credential-free collection; no endpoint probes        |
| `make test-integration`                                      | Real LLM, Ollama and API tests                        |
| `make test-integration-llm` / `make test-integration-ollama` | Selected live provider suites                         |
| `make test-smoke-ollama`                                     | Bounded model warmup/connectivity request             |
| `make test-hardware-cuda`                                    | GPU check; optional CUDA PyTorch install required     |
| `make docs-build`                                            | Strict docs build                                     |
| `make build-package`                                         | Verify the backend/frontend wheel and sdist sets      |

Tests use `N=4` workers by default; reduce `N` for rate limits or use `N=0` for serial diagnostics.
Focused targets accept `ARGS` filters; `test-all` rejects them.
Plain pytest selects offline suites. Coverage instrumentation is not configured;
UI simulations and synthetic artifacts do not prove a browser, container or installed wheel works.

## Writing tests

| Folder                 | Tests                                    |
|------------------------|------------------------------------------|
| `tests/unit/backend/`  | Settings, LLM logic, isolated API checks |
| `tests/unit/frontend/` | NiceGUI components/pages                 |
| `tests/unit/tooling/`  | Release, docs, startup and test helpers  |
| `tests/integration/`   | Live LLM/Ollama/API tests and fixtures   |
| `tests/hardware/`      | Explicit GPU checks                      |

Keep live/UI fixtures scoped to their folders. Offline tests use synthetic settings;
endpoint probes run in integration fixtures, never at collection. Parallel tests share no state.
Live generation uses short prompts, a 64-token output limit and no optional Ollama reasoning.
Release tooling tests use isolated command substitutes and never publish.

## GitHub Actions

CI and release workflows run `test-all` on Python 3.14.8 with a dedicated runner-local Ollama service.
`INTEGRATION_OLLAMA_MODEL` overrides the default `qwen3.5:0.8b`. CI provisions the model, warms it
with `test-smoke-ollama`, then tests with explicit local settings, no cloud credentials,
`INFERENCE_TIMEOUT_SECONDS=180` and `CHAT_TIMEOUT_SECONDS=240` for queued CPU requests.
The service is stopped after testing; logs and `reports/integration.json` / `integration.xml`
are included in `integration-results`. Summaries report failures even when setup prevents execution.

Static hooks cover syntax/whitespace, Ruff, secrets, the lockfile, Markdown/spelling and strict docs.
Use `make pre-commit FILES="path/to/file.py path/to/guide.md"` for selected files.
Commitizen checks messages at commit time. See `.pre-commit-config.yaml` for enabled hooks;
image/Compose/runtime checks remain separate from software validation.
