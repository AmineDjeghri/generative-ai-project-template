# 1. Setup

Get a working development environment.

## Prerequisites

| Tool                    | Version                               | Needed for                                    |
|-------------------------|---------------------------------------|-----------------------------------------------|
| make, bash, git         | Ubuntu 22.04+ or macOS defaults       | everything                                    |
| uv                      | recent                                | everything; `make install-uv` installs it     |
| Python                  | >= 3.14.8, < 3.15 (`requires-python`) | everything; uv downloads it                   |
| Ollama                  | any                                   | optional: a local LLM (`make install-ollama`) |
| Docker + docker-compose | any                                   | optional: `make docker-compose`               |
| NVIDIA GPU + drivers    | —                                     | optional: the CUDA variants                   |
| gh CLI                  | any                                   | optional: `make release*` from a laptop       |

## Install

```bash
git clone https://github.com/AmineDjeghri/generative-ai-project-template.git
cd generative-ai-project-template
make install-dev            # backend + frontend + dev and docs tools, CPU (or: make install-dev-cuda)
make pre-commit-install     # git hooks: checks on commit, commit message format
cp .env.example .env        # LLM endpoints and keys (see .env.example)
make test-all             # required: unit/component and real LLM/Ollama/API integration
```

Install only one side: `make install-backend` (or `install-backend-cuda`), `make install-frontend`.
Production dependencies only: `make install-prod` (or `install-prod-cuda`).

## Run

| Command                     | Starts                                             |
|-----------------------------|----------------------------------------------------|
| `make run-backend`          | FastAPI on <http://localhost:8000> (docs: `/docs`) |
| `make run-frontend`         | NiceGUI on <http://localhost:8080>                 |
| `make run-frontend-backend` | both                                               |
| `make run-app`              | Ollama + both                                      |

## Local LLM (Ollama)

```bash
make install-ollama            # macOS (Homebrew) or Linux
make download-ollama-models    # OLLAMA_MODEL_NAME and OLLAMA_EMBEDDING_MODEL_NAME
make run-ollama                # serves on http://localhost:11434
make test-smoke-ollama               # one generate call
make test-integration-llm        # the LLM client against INFERENCE_* from .env
```

A cloud model instead: set `INFERENCE_*` / `EMBEDDINGS_*` in `.env` with
[LiteLLM model names](https://docs.litellm.ai/docs/providers).

## Docker

| Command                       | Runs                                           |
|-------------------------------|------------------------------------------------|
| `make docker-compose`         | backend, frontend and Ollama (CPU)             |
| `make docker-compose-cuda`    | the same with CUDA (`docker-compose-cuda.yml`) |
| `make docker-compose-rebuild` | rebuild the images first                       |

## GitHub login (only to release from a laptop)

```bash
gh auth login     # once: make release-version and make release-assets use it
```

## IDE

- Interpreter: `.venv/bin/python`.
- PyCharm: mark `backend/src` and `frontend/src` as Sources Root, `tests` as Test Sources Root.
- `.editorconfig` sets indentation and line endings (tabs in `Makefile` and `*.mk`).

`make help` lists every target.

## Comprehensive software validation

`make test-all` is the required comprehensive software check for users, developers and CI.
It includes every existing self-contained and real-service integration suite. Configure the services
and dedicated test credentials in [the testing guide](4.testing.md) before running it. A focused `make test-local` pass
does not
establish full validation. Missing services or skipped integration must be reported as incomplete.
Coverage and artifact/runtime checks remain explicit alongside this command.

## Tool-only environments

1. Use `make install-tools` for quality checks and documentation without application dependencies.
2. Use `make install-release` for packaging and release tools only.
3. Run `make pre-commit-install` once per checkout; checks and docs commands do not reinstall hooks
   or dependencies. `make install-dev` remains the full application/test environment.
